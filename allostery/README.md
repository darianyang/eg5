# Cluster-resolved allosteric network analysis (mdpath) of Eg5 ADP unbinding

Compare allosteric communication networks between the two Eg5 ADP-unbinding WE
simulations — `nomon` (WT) and `wmon` (+monastrol) — **resolved by the 6 shared
LPATH clusters**, using [mdpath](https://mdpath.readthedocs.io) (`~/Apps/mdpath`).

Each WE frame already carries a shared cluster label (0–5) in `auxdata/labels`
(see `../lpath/cluster_shared.py`). Those clusters are stages along the ADP-exit
coordinate, so one mdpath network per `(condition, cluster)` gives a
**path/reaction-coordinate-resolved** allostery comparison — 6 clusters × 2
conditions = 12 networks.

## Two comparison axes

* **Drug effect** — `wmon` vs `nomon` within a cluster: monastrol's allosteric
  footprint at each stage of exit.
* **Stage/path** — adjacent clusters within a condition: how the network rewires
  as ADP leaves.

The comparison currency is the **per-edge NMI** on a single shared reference
graph (same residues, same 5 Å proximity edges), so only edge weights differ.

## How the two hard problems are handled

**Timeseries continuity (dihedral *differences*).** mdpath's signal is the
frame-to-frame *movement* of a residue dihedral. The only genuinely continuous
timeseries in a WE run is the set of frames inside one `seg.nc` (5 frames,
uniform 10 ps spacing). We therefore compute wrapped dihedral differences **only
within a segment**, never across a segment/file boundary, and pool the resulting
*movements* (not raw frames) per cluster — exactly as mdpath pools movements
across replicas. A movement is assigned to cluster `c` only when **both** its
endpoint frames carry label `c` (a genuine within-state transition); boundary
movements are dropped and counted. All movements share the same 10 ps lag, so
pooling is apples-to-apples.

**No weights.** Two schemes are built and compared:
* `pooled` — every movement equal (robust, ignores WE weights).
* `weighted` — each movement carries its segment's WE walker weight, normalized
  within the cluster, used as histogram weights in a weight-aware NMI.

Because WE weights span ~120 orders of magnitude, the merge step reports the
**Kish effective sample size** `ESS = (Σw)²/Σw²` per cluster. If ESS is tiny the
weighted network is dominated by a few walkers and the pooled one is more
trustworthy; `compare_networks.py` also reports pooled-vs-weighted edge
correlation so disagreement is visible.

## Angles

`phi` (backbone) drives the mdpath networks, matching mdpath itself. `chi1` and
`chi2` (sidechain) movements are extracted in the same pass and stored alongside,
so sidechain-aware allostery can be folded in later without re-reading 232k
trajectory segments.

## Workflow

```bash
cd allostery

# 1. extract dihedral movements -> data/shards/<cond>_NN.h5  (SLURM array, 16 tasks each)
sbatch --export=COND=nomon scripts/submit_extract.sh
sbatch --export=COND=wmon  scripts/submit_extract.sh

# 2. merge shards -> data/movements_<cond>.h5  (+ per-cluster ESS report)
python scripts/merge_shards.py nomon wmon

# 3. build all 12 networks x {pooled, weighted} and run the comparison (SLURM)
sbatch scripts/submit_networks.sh

# 4. visualizations
python scripts/plot_nmi_heatmaps.py       # NMI-weighted contact maps + drug delta
python scripts/plot_drug_summary.py        # 4-panel drug-effect summary
python scripts/make_mdpath_viz.py          # STL pathway bundles + ChimeraX .cxc / network
python scripts/make_footprint_chimerax.py  # colour structure by per-residue |dNMI|
```

The reference PDB (`data/ref_nomon.pdb`, protein only, AMBER numbering) is
generated by `build_reference_pdb` and used for every network.

## Outputs

* `data/movements_<cond>.h5` — per-angle movement matrices, WE weights, cluster ids.
* `networks/<cond>/cluster<c>_<scheme>/` — `nmi.csv` (edge weights),
  `paths.pkl` (top max-weight paths), `meta.json` (n_move, ESS, params).
* `networks/comparisons/` — ranked ΔNMI edge tables and per-residue involvement
  changes for each drug/stage comparison, `network_summary.csv`,
  `pooled_vs_weighted_agreement.csv`.
* `plots/drug_footprint_<scheme>.png` — per-residue monastrol allosteric
  footprint across clusters.
* `plots/nmi_heatmaps/` — sequence×sequence NMI-weighted contact maps
  (`grand_grid`, per-cluster), with the wmon−nomon difference map per cluster.
* `plots/drug_summary_<scheme>.png` — network divergence, dominant-pathway
  turnover, weighting confidence, and top drug-affected residues per stage.
* `viz/<cond>/cluster<c>_<scheme>/` — mdpath pathway **bundles**:
  `cluster_meshes/*.stl` (tube per bundle) + `open.cxc` (`chimerax open.cxc`).
* `viz/footprint/` — ChimeraX `.defattr` + `.cxc` colouring the structure by
  per-residue |ΔNMI| involvement (per cluster and peak-over-stages).

## Reading the comparison (finite-sample NMI bias)

Pooled NMI has a **finite-sample upward bias**: a cluster with fewer movements
shows systematically higher NMI everywhere. So raw ΔNMI *magnitude* (e.g. the
`drug_summary` panel A / top-residue ranking) is dominated by the per-cluster
movement-count difference, not by monastrol — the small clusters (1, 4) look
"most affected" only because they are undersampled. Trust instead: **(a)** the
dominant-pathway turnover (top-path Jaccard; set overlap, ~bias-free), **(b)**
the *localized structure* of the ΔNMI contact maps in well-sampled clusters
(2, 5; ESS in the thousands), and **(c)** within-cluster rankings. A
bias-controlled comparison (match both conditions to equal movement count per
cluster before NMI, or a Miller–Madow / mdpath-bootstrap correction) is the
recommended next step before quantitative cross-stage claims.

## Scripts

* `scripts/eg5_allostery.py` — extraction library + CLI (one shard).
* `scripts/submit_extract.sh` — SLURM array extraction (per condition).
* `scripts/merge_shards.py` — merge shards, report ESS.
* `scripts/build_networks.py` — NMI (pooled + weighted) → graph → paths per network.
* `scripts/submit_networks.sh` — build all networks + compare (SLURM).
* `scripts/compare_networks.py` — drug/stage ΔNMI, per-residue footprint, overlaps.

## Notes / possible extensions

* **Cluster 1 is small** (~7–9k frames in both) → lowest ESS; treat its weighted
  network with caution.
* **Sidechain dynamics** — `chi1`/`chi2` are already stored; extend the NMI to
  treat each angle as a feature (or aggregate per residue).
* **Inter-iteration transitions** — v1 uses only within-`seg.nc` movements; a
  parent→child trace would recover the (also continuous) iteration-boundary
  transitions for ~25% more movements.
* **haMSM steady-state weights** exist in both run dirs and would be a more
  principled weighting than raw WE weights.
